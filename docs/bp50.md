## 0. Vocabulary

- **OOB** = out of bounds · **IB** = in boundary. `lo boundary = 15`, `hi boundary = 85`.
- **etf** — the exhaustion TF chosen by x-cross-pred.
- **current_tf / rung** — the climb ladder's current TF (the `EXHAUST cur=sNN` value). Distinct from `etf`.
- **delegate split** — the rule mapping `etf` → the delegate TF. §4.
- **catch-many** — the fixed delegate used at or below the split.
- **x-cross-pred search range** — the TF window the exhaustion search scans: `rung` down to
  `max(xcp_tf_floor, rung − xpred_band)`, engaged only while `rung >= xpred_thresh`. With rung 90 and
  `xpred_band` 5 that is TF **85→90**; below the threshold it runs down to `xcp_tf_floor` (12).
- **rpl cycle band** — the TF partition selecting which r config a line uses: `TF<=s2_top → s2`,
  `s2_top<TF<=s8_top → s8`, `TF>s8_top → htf` (currently 2 / 8). Set by `MINI`'s `s2.r.*` / `s8.r.*` /
  `htf.r.*` keys.

> These two are **different partitions** and must never both be called "band". The x-cross-pred search
> range is a moving window under the climb rung; the rpl cycle band is a fixed 3-way TF split.

> **Naming rule:** use Joe's terms. Do not coin shorthand for a mechanic — ask him to name it.
> ("band" alone is ambiguous — see the two definitions above; always qualify it.)

## 3. Setup and trigger

### 3.1 `qualify()` — the setup

Per-episode, not per-bar. For each contiguous s4M OOB episode on a side:

- dwell: the first bar where `te[j] − te[start] >= DWELL_S*1000` (240 s)
- hs60x: OOB on the same side **at any bar in the episode** — it latches, it need not be OOB on the dwell bar
- **onset = `max(dwell-met bar, first hs60x-OOB bar)`** — one onset per episode

*Was:* a same-bar conjunction (`sustained_oob & hs_oob`) with the rising edge taken as the onset. That was
inference, and it could emit two onsets from one episode if hs60x flickered. Inert on 06-13 (hs60x was OOB on
100% of every episode's bars) — the change is unverified on that date.

### 3.2 `trigger()` — the setup latch

The setup latches at the onset and holds until it fires branch A/B **or hs60x breaches the opposing
boundary** (`hs <= LO` for a hi setup, `hs >= HI` for a lo setup). Detection is the raw first bar past the
boundary; the unlatch bar is **exclusive**. No opposing breach before tape end → scan to end of tape.

**There is no time cap.** The prior 5 h cap was inference.

### 3.3 Branch routing

`SS = _r_same_side(r, de)` — r on the same side of 50 as the **breach** `de`. Same-side on either HTF latches
**branch A**, one-way, never demotes. Before the latch, **branch B** is eligible.

| branch | cross pair | extra condition |
|---|---|---|
| **A** | `x × Mage` **or** `m × Mage` (per TF, `a_variant='both'`) | `A_MAGE_OOB`: s15M or s22M OOB |
| **B** | `x × m` | x OOB |

HTFs = (15, 22). Cross direction `d = −de`. All crosses are wob-debounced at `WOB=6` — 6 consecutive event
bars (30 s) on the crossed side, one bar back resets.

> wob=6 is good. it saves us from early firing

### 3.4 RGATE latch

RGATE is the gate line `gtr2` (a k-line at `GATE_TF=2`) same-side of 50 vs the breach `de`. It **latches on
its first same-side bar and holds for the setup's life**. A cross arriving before the latch is **skipped**
(`continue`) — the walk keeps scanning.

*Was:* a per-bar test at the fire bar, and failure did `break`, terminating the whole walk. That was
inference, and it was the mechanic that suppressed the 06-13 05:52 long: gtr2 was 19.6 when the setup
latched at 05:34:50 but 64.1 at the 06:16:50 cross, so the per-bar test killed a trade the latch admits.

## 4. The delegate split

`optimus9/orchestration/rpl_walk.py :: delegate_tf(etf)` — **the one definition**. `_climb_to_prov` calls it;
`build_delsweep.py` sweeps `CATCHMANY` through it.

```
etf >  xpred_thresh  ->  dTF = max(delegate_tf_floor, etf - delegate_offset)     # the -5 lookback
etf <= xpred_thresh  ->  dTF = max(delegate_tf_floor, catch_many_tf)             # the catch-many delegate
```

Split point is `xpred_thresh` (30) — the **same knob** that gates the x-cross-pred TF restriction, so tuning
the split moves both. Comparison is **strict** (`>`). `delegate_tf_floor` applies to both arms.

*Was:* `dTF = max(DELFLOOR, etf − DELOFF)` for every TF, which sent `etf=15` to s10 — the application Joe's
spec excludes.

**SRP:** the rule is a producer, not an expression inside the walk. `_climb_to_prov` orchestrates the climb;
it does not own the delegate policy. Precedent: `_climb_to_prov` was itself an extract-method lift out of
`_climb_flip`, and `s_qualify_parts` was split out of `s_qualify` for the N-of-9 gate. The jig doc states it —
*"If a verdict isn't packaged yet, split the producer first, then expose the split."*

## 6. `rpl_micro` — the report surface

> the table is for genuine trades

One chain per **`(fire_ts, tf)`**. Overlapping setups all latch and converge on the same cross, so chains
sharing that key are collapsed at **write time**, keeping the **earliest onset**; the `qualify` row records
`[+N overlapping setups collapsed]`. Dedup is deliberately *not* done in `qualify()` — suppressing onsets
there deletes setups rather than merging them, and would move which trades exist.

Missed / non-firing candidates are **not** recorded — Joe reads those off a chart.

Trigger row format:

```
branch-A s22 x*Mage; MageOOB s22M=13.1; RGATE latched 05:34:50 gtr2=19.6 (now 64.1)
```

`m_lines` carries `gtr2_latch` (the gate value at the latch bar) alongside `gtr2_r` (at the fire).

Schema is unchanged: `m_id · m_tid · m_tf · m_day · m_fire · m_branch · m_de · m_mode · m_seq · m_mechanic ·
m_time · m_decision · m_lines · m_built`. `m_tid = mmdd_NN`, finisher-ordered, fired-only.

## 7. Causality

at index `i`). Audited causal: `cross_wob`, `_sustained_oob`, `s3s4_gate`, `_stage`/`finish`, `_slope_flip`,
`_mage_rev`, `_rolling_any`, `s_qualify_parts`, `predict_breach`, `fin_unlatch_nof9` (trailing window only;

Known forward-looking idiom, **not** in the bp50 path: `lr_v2.py:110-111` (`nxt_hi`/`nxt_lo`, reversed
accumulate) inside `v2_arm`, used only to precompute an arm's cancel deadline. Safe as used; it becomes real
look-ahead the moment `cap`'s *value* feeds a decision at bar `i`.

Two index-0 artifacts: `np.roll(arr, 1)` wraps the tape's last element into position 0; `_px_smooth_evt`
backfills leading warmup NaN with the first finite value. Both warmup-region only.

### 10.2 What x-cross-pred actually is

Three conditions, all on the same bar (`_climb_to_prov`):

```
x down-crosses r   AND   near_ib(r)   AND   s2r on the exhaustion side of 50
```

- **The cross reference is `r`, not Mage.** `fx_bull = _dn(x − r)`. Mage appears only as `predict_breach`'s
  anchor and in bp50's branch A.
- **`rpl_flow_spec.md:72` permits three references — `x−r`, `x−M`, `x−HI`. Only `x−r` is ported.** So an
  `x × Mage` exhaustion is spec-restoring, not a new mechanic.
- **`near_ib` is a LEVEL test, not a timing one** — `r > HI − xcp_bnd_offset`. It is true at r=82 (approaching)
  *and* at r=96 (deep OOB for 40 min). The spec's stated intent was to stop crosses firing too early; it has
  no provision for firing too late.
- **`vmin` (8.0, "x-cross-pred coarse-velocity floor") is a DEAD knob** — seeded in `rpl_config`, read by
  nothing. It is the fingerprint of a predictive design that was specced and never wired.
- **Despite the name there is no prediction in it** — `_dn` is a completed cross. The only genuinely predictive
  element in the chain is the r-pred (`predict_breach`).

### 10.4 The race defeats per-cross filters

Exhaustion is `cand.sort(); cand[0]` — **earliest bar across every TF in the x-cross-pred search range wins**.
With six TFs (85–90) all convulsing on the same disturbance, removing one spurious cross promotes the next:

```
kill s89's spike (origin dwell)  ->  s88 crosses at 18:29:00, fifteen seconds later
```

Any filter that judges a single cross in isolation gets routed around. A filter on *r's subsequent behaviour*
would not, because it applies to whichever TF wins.

### 10.5 Two definitional collisions

**`rpred` is two clauses**, and the second collides with the exhaustion's own entry condition:

```python
rpred = (P[TF][i] == CS) or oob_climb(r)     # predicted to breach  OR  r already breached (r >= HI)
```

An exhaustion requires `near_ib(r)` — r at/past the boundary — so **any exhaustion with r ≥ 85 is r-pred by
definition**. Applied literally, "ignore the event if r-pred" rejected **30 of 31** crosses on 06-13. Testing
only the `predict_breach` clause is the workable reading (48% survive, chains 1/2/4 keep their exhaustions).

**`predict_breach` switches off during a breach** (`rpl_flow_spec.md:47` — "Predict-only collapses the frontier
to 0 during a breach run"). So a deeply-breached r can never be invalidated by an r-pred retest: chain 1's
r=97.7 has no prediction to fire. The retest bites hardest where r sits *just below* the boundary.

## 14. The lower-TF hunch — reproduced, then killed by its own null (0729)

Joe's hunch after §13: *"comparing the mid-leg signals against a exhaustion cross at a lower TF might show
a thread."* The aggregate run answered it 95.7% yes. **That number reproduces and is still not evidence.**

### 14.1 It reproduces

Candidate pool per applied event = every `rpl_exhaust` row with the same bias (`xh_bias` = `ep_bias`), a TF
strictly below the fired rung (`xh_tf < ep_cur_tf`), and a raw bar inside the containing swing_detect(2%)
leg. Position in leg computed exactly as `ep_pos_in_leg` (0.0 = leg start, 1.0 = the pivot ending it).
Ties in position broken to the **highest** TF, which is the conservative choice — it minimises the claimed
TF gap.

```
  applied events with a lower-TF marker in the same leg   207
  a lower TF sat NEARER the pivot                         201  (97.1%)
  position: fired 0.45  ->  best available 0.96
  TF gap (fired minus better):  med 18   p25 5   p75 41
```

The gap quantiles match the original run exactly; the rate is 201/207 rather than 198/207 (3 rows, filter
detail not recovered). The direction is identical. **Reproduction was never the problem.**

### 14.2 The null — a scatter of the same size does better

The pool is dense. Per leg: **median 347 candidate markers across 57 distinct lower TFs** (p25 138, p75 652,
max 4,003). `rpl_exhaust` holds 170,239 rows over 26 real days × TF22–120 × 2 biases, so any leg contains
hundreds of markers and "one of them sat near the pivot" is close to guaranteed before any mechanic is
consulted. Null = draw the **same number** of positions uniformly across the leg and take the max:

| | best marker position in leg | "a lower TF sat nearer" |
|---|---|---|
| observed | **0.960** | **97.1%** |
| N random bars, same N per leg | **0.998** | **100.0%** |

**The observed value is below its own baseline on both columns.** 0.96 is not the mechanic finding the
pivot; it is the largest of ~347 draws, and real markers cluster, so they reach it slightly *less* often
than scatter does.

The winning TF is also unstable — median 45, p10 23, p90 99, full range 22→119, and the most frequent single
winner (TF22) takes 14 of 207. There is no TF or band that keeps winning, so there is nothing to select on.

### 14.3 Thin the pool to one marker per TF and the answer becomes the thinning rule

A selection rule picks a **TF**, not a marker, so the fair pool is one marker per TF per leg (57 entries,
not 347). Which marker you keep decides the result:

| marker kept per TF | best real | null | fired beats a random alternative TF |
|---|---|---|---|
| earliest in leg | 0.362 | 0.988 | **92.8%** |
| median in leg | 0.763 | 0.987 | 61.4% |
| random in leg | 0.917 | 0.985 | 64.3% |
| latest in leg | 0.960 | 0.990 | **31.9%** |

Swinging from 92.8% to 31.9% on a choice nobody specified means the comparison is **indeterminate**, not
favourable and not damning. The one column that is stable is the null: `best real` sits below it in every
row.

### 14.4 What this retracts

The claim *"the signal is not missing — the selection is wrong"* is **withdrawn**. It was hindsight mining
of a dense pool. Three things were hung off it and now have no support from this measurement:

- that it explains **task #7** (branch 1 firing 2 of 208),
- that **`xpred_band` measures better than what replaced it**,
- that **seed TF and exhaustion TF should be different things**.

Each may still be true. None of them is evidenced here, and #7 has a direct cause already recorded in §1
(seeding on the highest *participating* TF lands high, so leg b wins the race before a non-established r can
be crossed).

**§13.1 is unaffected and still stands**: exhaustions sit at median position 0.50 in their leg with
direction correct 40.5% against a 49.2% baseline. The lower-TF hunch was the first attempt to explain that
away, and it does not.

### 14.5 Repro

The whole measurement is four steps against two tables:

1. `SELECT * FROM rpl_exh_pivot` — 207 applied events with their containing leg (`ep_leg_start_utc`,
   `ep_leg_end_utc`, `ep_cur_tf`, `ep_bias`, `ep_pos_in_leg`).
2. `SELECT xh_tf, xh_bias, xh_raw_ms FROM rpl_exhaust` — 170,239 candidate markers.
3. Per event: keep markers with matching `xh_bias`, `xh_tf < ep_cur_tf`, `xh_raw_ms` inside the leg; position
   = `(xh_raw_ms − leg_start_ms) / (leg_end_ms − leg_start_ms)`.
4. Null: per event draw `len(pool)` uniform positions, take the max, and compare medians across the 207.

Leg bounds are stored as UTC strings; parsing them as UTC and recomputing `ep_pos_in_leg` agrees with the
stored value to 0.006, which is the 5 s grid.

  has passed and the favourable leg is already under way — `MAE-before-MFE` is **89/89 (100%)** for dir WRONG,
  a small adverse tick then the move.
- **This contradicts the stated target** (*"land exhaustion bars just before swing_detect(2%) pivots"*).
  On MFE/MAE, just **after** is better. Joe 0729: *"16 minutes after our average HTF pivot is still in a
  retest phase, minimal drop in pnl."*
- **§13.1 is not withdrawn, it is re-read.** Its 40.5% "below chance" is arithmetically correct and scores
  anticipation of the pivot. It does not score what the trade gets, and the two point opposite ways.

## 12. x-cross-pred — what it is, and the TF-alignment finding (0728)

### 12.1 The model reached

All terms causal, readable at the bar. `h = x − r`.

```
near_ib(r)      r at the boundary (the engine's own gate)
h > 0           x still above r, not yet crossed
x < 100         x has descended into the band
re-arm only after an actual x-r cross (observable live)
```

|---|---|---|---|---|---|
| s45 | 132 | 98% | 97% | 20 s | 105 s |
| s60 | 90 | 99% | 100% | 20 s | 49 s |

**The honest limit: ~20 s median lead is confirmation, not forecast.** Feature discrimination on TF75

### 12.2 The cross-TF question — answered negative

Joe: *"should you be testing against lower TF crosses from a higher TF prediction?"* Swept delegate offset
−11 → −1, both directions of time.

- **Forward** (does the prediction lead the delegate's cross): led% 5–44%, and it only improves as the
  offset shrinks toward −1, where the delegate is nearly the prediction TF itself. That is leakage.
- **Backward** (had the delegate already crossed): no. Only 4–56% within the prior 300 s; the median age of
  the delegate's last cross is **hours**.
- **Why**: at the prediction instant, `near_ib(delegate r)` holds only 27–90% of the time and x is OOB on
  the delegate only 36–86%. Median `|Δr|` between a TF and its delegate is 3.5 at −5, 12.4 at −11; the two
  are jointly `near_ib` only 40–86% of the time.

x-cross-pred's lead is **strictly local to its own TF**. It carries no information about any other TF's
cross, in either time direction. Joe's `near_ib` correction (§1, 0728) follows directly: requiring
`near_ib` on the *delegate's* r was the wrong gate — it belongs on `current_tf`.

### 12.4 The delegate-band test — designed, not built

Joe's design in §1 (0728). Built as **`build_bandlab.py`** — research file; no gated file touched.

**Fire rule — CONFIRMED by Joe 0728.** *lo side — fire when x crosses up through `min(lo_boundary, r)`;
hi side — down through `max(hi_boundary, r)`*: the nearer of the two thresholds. Joe wrote only the `r` IB
case ("we fire on the x cross boundary"); the `r` OOB row — fire on the **r** cross, because r is then the
nearer line — was inferred, put to him explicitly, and confirmed.

**"early" — DEFINED by Joe 0728**: *"we don't don't want the delegate to create a more granular cross that
isn't aligned with current_tfs impending cross."* Scored as three outcomes from the delegate fire, with no
cap (`current_tf` searched to end of tape):

| outcome | meaning |
|---|---|
| `aligned` | `current_tf`'s cross landed **before** the delegate's x flipped back |
| `early` | the delegate's x flipped back **while `current_tf`'s cross was still outstanding** |
| `none` | `current_tf` never crosses at all — the same failure, terminal form |

*Wording is Joe's (0728). The earlier phrasing — "current_tf crosses while the delegate's cross still
stands" — reads backwards, because "standing" can mean "still pending". Same test either way:
`flip_back_index < current_tf_cross_index` → early.*

This replaced a lead-vs-baseline metric that was **not usable**: median lead ran to +24,780 s with p25 at
−33,830 s, because the baseline needs an x-cross-pred (exhaustion + `near_ib` + `s2r`) and the band mechanic
needs none of it, so the two fire on unrelated occasions hours apart. Dropping it also removed the 490
scalar `_climb_to_prov` calls, so the sweep no longer takes 40 min.

#### Measurement errors found and fixed — read before trusting any band number

| error | symptom | fix |
|---|---|---|
| `held_at_seam` tested x against `HI`/`LO`, but the fire threshold is `max(HI, rD)` | inflated the aligned-vs-unaligned gap to 31 pts when the standalone base rates differ by 4–6 | metric replaced entirely by `outcome()` |
| `current_tf`'s cross searched from `k+1`, excluding the fire bar | the `cur` control read **0% aligned / 100% early** — impossible, since when `dTF == rung` the delegate's cross *is* `current_tf`'s cross | search from `k` inclusive; `cur` now reads 100%, the intended sanity check |
| reversal tested on **raw** state while the fire is debounced at `wob_n`=9 | one 5 s flick past the threshold counted as a reversal; `early` inflated on every arm | reversal must clear the same `wob_n`, opposite direction — no new knob |
| `aligned` arm used nearest divisor of 1440 **at or below** `rung` | median rung is 90 and 90 divides 1440, so the arm collapsed to `cur` and inherited its 100%-by-construction score (5 s median gap gave it away) | strictly **below** `rung` |

**The confound that matters most.** `aligned%` conflates two independent quantities: how long the delegate's
cross actually stands (**HELD** — a property of the delegate) and how long it is *required* to stand
(**REQ** = delegate fire → `current_tf` cross — a property of the gate's timing). `aligned ⇔ HELD ≥ REQ`.
Within `root60`, D=4 gives REQ 1850 s and 28% aligned; D=5 gives REQ 390 s and 47%. The delegate did not
improve — it was asked to hold for 6 min instead of 31. **Arms are only comparable at equal REQ**, and at
D=4 `root60` REQ is 1850 s against `ctl_un` 1200 s. HELD and REQ are therefore reported separately.

**Also**: `none` never fires (0% at every arm and D). With no cap, `current_tf` always crosses eventually,
so the category is vacuous by construction — not evidence that the delegate always leads something real.

## 18. r-pred — persisted at the producer, cancelled by the cross, gated by clean/dirty (0730)

Full spec: **`docs/rpred_spec.md`**. This section is the finding trail; the spec is the mechanic.

### 18.1 The defect

`predict_breach` emits a per-bar STATE. Nothing recorded WHEN it turned on, so every r-pred timestamp was
reconstructed downstream. Three derives on `0520 17:58` s119 gave `16:34`, `15:52`, `16:34`.

Worse, the state survives its own invalidation. s69 dir +1: an r-pred at `0518 20:42` running **8.2 min**
still counted as participating at the `0520 10:26` exhaustion — **37.75 h later**. 2,257 of those 2,265
minutes had no live r-pred at all.

### 18.2 Three changes

1. **The r-pred moment is stamped in `build_rplwalk2.applied()`** at the confirmed marker bar, by the code
   that already decides `ea_cur_tf`. Columns `ea_rpred_ms/_utc/_end_ms/_bars/_label`, carried to
   `rpl_exh_stat` as `es_rpred_*`. No downstream derive remains.
2. **The r-pred run is a latch** — set on the `predict_breach` rising edge, reset by the polarity-matched
   x/r cross (`fx_bull` bull, `fx_bear` bear). Set wins on ties. `oob_climb` never cancelled.
3. **A clean/dirty flag per `(tf, dir)`** gates the predict term in `rp_matrix`. Dirty ← an exhaustion
   prints anywhere while the line is outside its fence. Clean ← x crosses back through r on that line.
   Lines start dirty. Fence crossings debounced at `WOBN` = 9 bars = 45 s.

### 18.3 Why the boundary is not the dirty trigger

r frequently never goes OOB. **65 of 208** applied exhaustions fire with r inside the 30/70 fence, only 7
with r OOB. 205 of 208 are leg b — **x** crossing the boundary, which says nothing about r.

### 18.4 Why clean is the x/r cross, not fence re-entry

18,334 r-pred episodes from 05-18:

```
clean = r re-enters the fence   -> suppressed  5238 (29%)   5069 of them CROSS-LINE
clean = x crosses back thru r   -> suppressed   526  (3%)
  RELEASED by the x/r rule      : 4743 of 5238  (91%)
  still suppressed under both   :  495
```

The fence rule kills s22 episodes with r at **84.81-84.98** against `HI` = 85 because an s45 exhaustion
printed. The x/r rule releases them. The 495 survivors are exactly: exhaustion printed, line outside its
fence, x not recovered above r.

### 18.5 The `2nd x r-pred` label (Joe)

Dirtied by an exhaustion on a **higher TF**, x recovered through r, **and** x returned OOB.
`2nd r-pred` = same minus the x-OOB return. Full applied set: `r-pred` 169 · `2nd x r-pred` 38 ·
`2nd r-pred` 1.

### 18.6 The two-pass, and whether it survives live

`rp_matrix` needs the flag → the flag needs exhaustions → `applied()` produces them → needs `rp_matrix`.
Circular in batch, **not live**: at bar `i` the flag reads only exhaustions already printed, so live is one
forward pass. Batch iterates: `144 → 147 (-1 +4) → 147 (-0 +0)`, converged at pass 3.

**OPEN:** convergence is evidence, not proof. A bar-by-bar causal simulation has not been built.
